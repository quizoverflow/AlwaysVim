# MSVC 빌드

Visual Studio의 **x64 Native Tools Command Prompt**에서 이 폴더로 이동한 뒤 실행합니다.

```bat
cl /nologo /std:c++17 /EHsc /O2 /MT /Fo"%TEMP%\VimAgent-main.obj" main.cpp /link /SUBSYSTEM:WINDOWS /OUT:VimAgent.exe user32.lib gdi32.lib
```

Windows용 C++ 데스크톱 개발 도구와 Windows SDK가 필요합니다. 명령은 현재 폴더에 `VimAgent.exe`를 만들고 중간 오브젝트 파일은 `%TEMP%`에 둡니다. `/MT`는 C++ 런타임을 정적 연결합니다. Windows 시스템 DLL은 필요합니다. 기존에 폴더에 있던 `main.obj` 같은 파일은 자동으로 삭제하지 않습니다.

Developer PowerShell에서는 환경 변수 문법이 다르므로 다음 명령을 사용합니다.

```powershell
cl /nologo /std:c++17 /EHsc /O2 /MT "/Fo$env:TEMP\VimAgent-main.obj" main.cpp /link /SUBSYSTEM:WINDOWS /OUT:VimAgent.exe user32.lib gdi32.lib
```

`cl main.cpp`만 실행하면 기본 출력 이름과 진입점 설정을 사용하고, 이 프로그램이 사용하는 Windows 라이브러리도 명시하지 않아 연결 오류가 날 수 있습니다. 위 명령은 GUI 실행 파일을 지정하고 `user32.lib`, `gdi32.lib`를 연결합니다. 실행 중인 `VimAgent.exe`는 X 버튼으로 종료한 뒤 다시 빌드하세요.

# VimAgent 명세서

## 목적과 실행 환경

VimAgent는 Windows에서 활성 프로그램의 키 입력을 감시하고, 일부 Vim 명령을 일반 편집기의 키 조합으로 바꿉니다. 별도의 편집기 플러그인은 필요하지 않습니다. 모든 Vim 기능을 구현하는 프로그램은 아니며, 대상 프로그램이 Windows의 방향키, 선택, 복사 및 붙여넣기 입력을 처리해야 합니다.

`VimAgent.exe`를 실행하면 현재 활성 창이 있는 모니터의 왼쪽 아래에 상태창이 표시됩니다. 상태창은 포커스를 가져가지 않으며, 모드 텍스트 영역을 통한 마우스 클릭은 아래 창으로 전달됩니다. 오른쪽의 두 버튼은 클릭할 수 있습니다.

| 표시 또는 조작 | 동작 |
| --- | --- |
| `INSERT` | 일반 입력 모드. 시작 시 기본 모드입니다. |
| `NORMAL` | Vim 명령을 받는 모드입니다. |
| `VISUAL` | 이동할 때 대상 편집기의 텍스트 선택을 확장합니다. |
| 일시 정지 버튼 / `Ctrl+Alt+F12` | 키 변환을 끄거나 다시 켭니다. 정지 중에는 `PAUSED`가 표시되고 버튼이 재생 모양이 됩니다. 이전 모드는 유지됩니다. |
| X 버튼 / `Ctrl+Alt+Shift+F11` | 키보드 후크를 해제하고 프로그램을 종료합니다. |

모드와 대기 중인 명령은 앱 전체에서 공유합니다. 대상 창을 바꿔도 모드는 자동으로 바뀌지 않습니다. 일시 정지하면 미완성 명령은 취소되지만 대상 앱의 기존 선택 영역은 그대로입니다.

## 키 명령

### Insert 모드

일반 키 입력은 대상 앱으로 전달됩니다. `Esc`를 누르면 해당 키는 대상 앱으로 전달하지 않고 Normal 모드로 바뀝니다.

### Normal 모드

| 키 | 동작 |
| --- | --- |
| `i` / `I` | 현재 위치에서 입력 / 줄 시작으로 이동한 뒤 입력 |
| `a` / `A` | 오른쪽으로 이동한 뒤 입력 / 줄 끝으로 이동한 뒤 입력 |
| `o` / `O` | 현재 줄 아래 / 위에 줄을 추가하고 입력 |
| `h`, `j`, `k`, `l` | 왼쪽, 아래, 위, 오른쪽으로 이동 |
| `w`, `b` | 다음 / 이전 단어 경계로 이동 (`Ctrl+방향키`) |
| `0`, `^`, `$` | 줄 시작, 줄 시작, 줄 끝으로 이동 |
| `gg`, `G` | 문서 시작 / 끝으로 이동 (`Ctrl+Home`, `Ctrl+End`) |
| `v` | Visual 모드 시작 |
| `yy` | 현재 줄을 선택해 클립보드에 복사. 개행이 있으면 개행도 포함합니다. |
| `y` + 이동 명령 | 이동 범위를 선택해 복사. `h`, `j`, `k`, `l`, `w`, `b`, `0`, `^`, `$`, `gg`, `G`를 지원합니다. 예: `yw`, `y$`, `ygg`. |
| `p` | 클립보드 내용을 현재 위치 뒤에 붙여넣기. 이 프로그램에서 마지막으로 `yy`로 복사한 내용이면 현재 줄 아래에 붙여넣습니다. |

`gg`의 두 `g`는 500ms 안에 입력합니다. `y`와 그 이동 명령 전체는 1초 안에 입력합니다. 키를 누른 채 발생하는 자동 반복은 `gg`나 `yy`의 두 번째 입력으로 취급하지 않습니다. `P`, 횟수 접두사, 다른 연산자와 명령은 지원하지 않습니다. Normal 모드에서 처리하지 않는 문자 키는 대상 앱에 입력되지 않습니다.

### Visual 모드

`h`, `j`, `k`, `l`, `w`, `b`, `0`, `^`, `$`, `gg`, `G`는 각각 Shift가 포함된 이동 키를 보내 선택 영역을 확장하거나 줄입니다. `y`는 선택 영역을 시스템 클립보드에 복사하고 Normal 모드로 돌아갑니다. `Esc`도 Normal 모드로 돌아가며, 이동으로 만든 선택 영역은 왼쪽 방향키로 해제합니다.

선택은 대상 앱의 일반적인 Shift 선택을 이용합니다. `v`만 눌렀을 때는 선택이 생기지 않고 첫 이동부터 만들어지며, 선택 끝점 포함 여부는 Vim의 문자 단위 Visual 모드와 다릅니다. 선택 결과는 대상 앱의 커서 위치와 줄바꿈 처리에 따릅니다.

### 클립보드와 줄 복사

복사는 대상 앱에 `Ctrl+C`, 붙여넣기는 `Ctrl+V`를 보내는 방식입니다. 따라서 기존 시스템 클립보드를 사용하고 다른 프로그램에서도 복사한 내용을 볼 수 있습니다. `yy`는 `Home`, `Shift+End`, `Shift+Right`로 줄과 뒤따르는 개행을 선택합니다. 줄 단위 `p`는 현재 줄 끝에 새 줄을 만든 뒤 붙여넣고, 복사된 텍스트 끝에 개행이 있으면 그 개행을 하나 제거합니다.

복사 후 클립보드가 다른 프로그램 등에서 변경되면 줄 단위 정보가 지워지고, 이후 `p`는 일반 문자 단위로 동작합니다. 줄 단위 정보는 이 프로세스가 실행되는 동안에만 유지됩니다. 클립보드를 잠시 열 수 없거나 텍스트 형식을 읽을 수 없으면 일반 붙여넣기를 시도합니다.

선택할 문자가 없는 **문서의 마지막 빈 줄**에서는 일반 편집기가 `Ctrl+C`로 클립보드를 갱신하지 않을 수 있어 `yy`를 복사로 인식하지 못할 수 있습니다. 줄 복사는 편집기의 `Home`, `End`, 개행 선택, `Enter`, `Backspace` 동작에 의존하므로 자동 들여쓰기나 줄바꿈 표시가 있는 편집기에서는 실제 Vim과 결과가 다를 수 있습니다.

## 동작 구조와 유지보수

소스는 `main.cpp` 하나입니다. `wWinMain`이 창을 만들고, 250ms 타이머와 `WH_KEYBOARD_LL` 키보드 후크를 등록한 다음 Windows 메시지 루프를 실행합니다. 상태창이 종료되면 타이머와 클립보드 알림을 해제하고 후크를 제거합니다.

| 구성 | 역할 |
| --- | --- |
| `AppState` | 현재 모드, 정지 상태, `g`/`y` 접두사, 클립보드 복사 종류, 실제 Shift 키와 키 해제 처리 상태, 창 핸들을 보관합니다. |
| `KeyboardHookProc` | 물리 키를 모드에 따라 해석하고, 처리한 키의 누름과 해제를 대상 앱에서 숨깁니다. Ctrl 또는 Alt가 눌린 일반 조합과 프로그램이 주입한 입력은 통과시킵니다. |
| `HandleNormalKey`, `HandleVisualKey`, `HandleYankMotion` | 모드별 명령과 `y` 뒤의 이동 명령을 처리합니다. 새 명령은 해당 함수에 추가합니다. |
| `SendChord` | `SendInput`으로 스캔 코드와 확장 키 플래그를 보내며 필요한 Ctrl/Shift를 구성합니다. 실제 Shift 상태를 후크에서 따로 추적해 연속된 주입 입력과 섞이지 않도록 합니다. |
| `CopySelection`, `PasteAfterCursor`, `RefreshClipboardYank` | 복사 및 붙여넣기 키를 보내고 클립보드 변경 순번으로 줄 단위 복사 여부를 관리합니다. 복사 결과 대기는 최대 1.5초입니다. |
| `PaintOverlay`, `ButtonWindowProc`, `PositionOverlay` | 모드와 버튼을 그리고, 포커스를 빼앗지 않고 화면 위치와 버튼 입력을 처리합니다. |

후크는 대상 프로그램에 키를 보내므로 대상 앱이 해당 입력을 지원해야 합니다. 관리자 권한으로 실행한 대상 앱에는 Windows 권한 정책 때문에 일반 권한의 VimAgent 입력이 전달되지 않을 수 있습니다. 터미널, 웹 앱, 게임, 보안 입력란이나 자체 키 처리 방식을 쓰는 앱에서는 선택과 단축키가 다르게 동작할 수 있습니다. 단어와 줄 이동은 대상 앱의 `Ctrl+방향키`, `Home`, `End` 구현을 따르며 Vim의 문법 분석이나 줄 단위 선택을 재현하지 않습니다.

## 수동 확인 방법

1. 메모장에 여러 줄의 텍스트를 입력하고 첫 줄에 커서를 놓습니다. VimAgent를 실행하고 `Esc`를 눌러 `NORMAL`을 확인합니다.
2. `v`를 누른 다음 `l`, `j`, `h`, `k`를 눌러 선택 영역이 생기고 이동에 따라 바뀌는지 확인합니다. `y`를 누르면 `NORMAL`로 돌아가는지 확인합니다.
3. `p`를 눌러 선택했던 내용이 붙여넣어지는지 확인합니다. 다른 내용을 복사한 뒤 `p`도 확인합니다.
4. 내용이 있는 줄, 빈 줄, 문서의 마지막 줄에서 각각 `yy`와 `p`를 눌러 현재 줄 아래에 복사되는지 확인합니다. 문서 끝의 빈 줄은 위에 설명한 제약이 있습니다.
5. 정지 버튼을 누르면 `PAUSED`가 표시되고 일반 타이핑이 전달되는지, 다시 누르면 이전 모드로 돌아가는지 확인합니다. X 버튼을 눌러 상태창과 프로그램이 종료되는지도 확인합니다.
